# 万哥牛逼输出排行设计

## 目标

在不增加常见路径 API 调用、不改变 Star 写入边界的前提下，让脚本输出每个公开仓库当前收到的 Stars，并生成完整、确定性的全局项目总榜。模型继续原样返回脚本生成的 `markdown`，不参与排序、徽章选择或文案组织。

## 数据设计

- GraphQL 仓库节点增加 `stargazerCount`，与现有账号、仓库和 `viewerHasStarred` 在同一次查询中取得。
- 内部仓库对象增加 `star_count`。
- JSON 报告增加：
  - `totals.stars_received`：全部目标项目的当前 Stars 之和，不表示唯一用户数。
  - `targets[].stars_received`：该作者所有公开仓库的当前 Stars 之和。
  - `ranking[]`：完整全局排行，包含 `rank`、`badge`、`owner`、`repository`、`full_name`、`url`、`star_count` 和 `state`。
- 现有执行状态、失败详情、API 统计和私有仓库声明继续保留。

## 排序与显示规则

1. 全部公开仓库按 `star_count` 降序排列。
2. Stars 相同时，按 `full_name` 不区分大小写升序排列，保证输出稳定。
3. 排名按最终行序连续编号；前三名显示 `🥇`、`🥈`、`🥉` 并加粗项目名，其余显示 `#4`、`#5` 等。
4. Stars 使用千位分隔符，显示为 `⭐ 1,234`。
5. 状态由脚本固定映射：
   - `✅ 原已 Star`
   - `🆕 本次新增`
   - `🧭 待新增`，仅 Dry Run
   - `⚠️ 失败`

## Markdown 结构

1. 标题：`# ⭐ 万哥牛逼｜执行报告`。
2. 摘要引用块：执行结果、已 Star 进度、本次新增、项目累计 Stars、执行账号和 API 调用数。
3. `项目总榜`：展示全部仓库，列为排名、项目、作者、当前 Stars、状态。
4. `作者概览`：展示每位作者的公开仓库数、项目累计 Stars、本次新增和失败数。
5. 仅在存在失败时输出失败详情。
6. 结尾保留“私有仓库按规则不查询、不操作”。

不再按作者重复输出仓库名称长列表；全局总榜同时承担完整详情和排序展示。

## 行为边界

- 目标仍固定为 `centitenka` 与 `KinomotoMio`。
- 只查询公开仓库，包含 fork 和 archived 仓库。
- 只允许添加 Star，不增加任何 Unstar 路径。
- 常见的 100 个以内仓库路径仍为一次 GraphQL；超过 100 个时继续按游标分页。
- GraphQL 或写入失败沿用现有 `partial`、错误净化和最终复核逻辑。

## 验证设计

- 排行按 Stars 降序，平分时按 `full_name` 稳定排序。
- 前三名徽章、加粗、千位分隔符和状态文案正确。
- Dry Run 使用 `🧭 待新增` 且不执行 PUT。
- 实际缺失场景仍执行“发现 → PUT → 全量复核”。
- 分页仓库进入完整排行，不遗漏第二页。
- PowerShell 7 与 Windows PowerShell 5.1 离线测试均通过。
- 官方 Skill 校验、PowerShell 语法、UTF-8 BOM 和 `git diff --check` 通过。

## 非目标

- 不引入缓存、外部模板、模型生成摘要、README 演示图更新或新的 GitHub 写操作。
- 不按 Star 数设置易漂移的绝对阈值；视觉强调只由全局前三名决定。
